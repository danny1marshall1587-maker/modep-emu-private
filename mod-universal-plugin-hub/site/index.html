📖 Developer Guide: Universal LV2 Multi-Architecture & Cloud Porter

Welcome to the developer documentation for creating, cross-compiling, and distributing universal plugins for the MOD Audio & MODEP ecosystems.

1. The Universal FAT Bundle Specification

An LV2 bundle is a folder containing a manifest.ttl descriptor and binary files. By declaring multiple lv2:binary statements with OS and CPU architecture constraints, a single bundle seamlessly executes across Windows, macOS, Linux, and Raspberry Pi:

@prefix lv2:  <http://lv2plug.in/ns/lv2core#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .

<http://cyber-audio.co.uk/plugins/my-overdrive>
    a lv2:Plugin ;
    lv2:binary <my_overdrive.dll> ;                  # Windows 64-bit
    lv2:binary <my_overdrive_linux_x86_64.so> ;      # Linux Desktop 64-bit
    lv2:binary <my_overdrive_armv7.so> ;             # Raspberry Pi 3/4 32-bit (MODEP)
    lv2:binary <my_overdrive_arm64.so> ;             # Raspberry Pi 4/5 64-bit (MODEP 64)
    rdfs:seeAlso <my_overdrive.ttl> , <modgui.ttl> .

2. Seamless Intel SSE → ARM NEON Vector Translation

If your DSP algorithms utilize Intel SSE/AVX intrinsics (_mm_add_ps, _mm_mul_ps), the Porter automatically includes sse2neon.h during ARM compilation. This maps all x86 vector registers directly to ARM NEON hardware with zero performance overhead.

3. Automated MODGUI Synthesis

If your LV2 plugin does not ship with a modgui/ web interface, the Porter inspects all lv2:ControlPort inputs in your .ttl files and generates an authentic HTML5/CSS3 pedal layout with touch-friendly rotating dials, bypass footswitch, and glowing LED indicators.

4. Integrating with Blokas MODEP & MOD Desktop

Simply drop the extracted .lv2 folder into:

  • 🪟 Windows (MOD Desktop): C:\Program Files\MOD Desktop\plugins\
  • 🍓 Raspberry Pi (MODEP / Patchbox OS): /var/modep/lv2/ or ~/.lv2/
  • 🍎 macOS (MOD Desktop): ~/Library/Audio/Plug-Ins/LV2/
  • 🐧 Linux (MOD Desktop): ~/.lv2/ or /usr/lib/lv2/
